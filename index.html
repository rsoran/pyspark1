Run PySpark in a Docker container (with VS Code)

No Java, Python or Spark install needed on your computer. Docker packages Python 3.11, Java (JRE), PySpark 3.5.3, pandas, numpy and pyarrow for you.

Step 0 – Install the tools

  • Docker Desktop (start it and wait until it says "running")
  • Visual Studio Code with the extensions Python, Docker and Dev Containers (Microsoft).

Step 1 – Check Docker works

Open VS Code, then Terminal → New Terminal.

docker --version

Step 2 – Open the project folder in VS Code

File → Open Folder… and choose this pyspark folder. It contains:

  • Dockerfile – recipe for the environment (Python + Java + dependencies)
  • requirements.txt – Python packages (pyspark, pandas, numpy, pyarrow)
  • app.py – a sample PySpark program
  • .devcontainer/devcontainer.json – lets VS Code work inside the container

Step 3 – Build the image (first time only, a few minutes)

docker build -t pyspark-demo .

The last lines show the image was created and named pyspark-demo.

Step 4 – Confirm the image exists

docker images pyspark-demo

Step 5 – Run the PySpark program

docker run --rm pyspark-demo

You should see Spark version: 3.5.3 and two tables. Spark's startup warnings (e.g. "Unable to load native-hadoop library") are harmless.

Step 6 – Edit code and run your own version

Edit app.py in VS Code, then run it using the live folder (no rebuild needed).

# PowerShell
docker run --rm -v "${PWD}:/app" pyspark-demo python app.py
# Command Prompt:  -v "%cd%:/app"

Quick version check:

Step 7 – Work inside the container from VS Code (recommended)

  1. Press F1 (or Ctrl+Shift+P) → Dev Containers: Reopen in Container.
  2. Wait for the build; the bottom-left corner shows Dev Container: PySpark.
  3. Open app.py and click the ▶ Run Python File button, or in the VS Code terminal run python app.py.
  4. To go back: F1 → Dev Containers: Reopen Folder Locally.

Interactive shell / PySpark REPL

docker run --rm -it -v "${PWD}:/app" pyspark-demo bash
docker run --rm -it pyspark-demo pyspark

Troubleshooting

  • "Cannot connect to the Docker daemon" – start Docker Desktop first.
  • Build is slow – normal the first time (image ≈ 1.6 GB); later builds use the cache.
  • Out of memory – Docker Desktop → Settings → Resources → raise memory to 4 GB+.
  • Windows: use WSL 2 backend (default in Docker Desktop).
